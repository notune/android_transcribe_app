# Security Screen: OVI-001

## Профиль риска

`standard`. Причины: новый сетевой вызов, новое разрешение `INTERNET`,
хранение секрета, отправка личного текста внешнему серверу, изменение
поведения трёх путей ввода.

## Класс данных и границы доверия

| Данные | Класс | Куда попадают |
|---|---|---|
| Аудио | личное, чувствительное | только память телефона |
| Распознанный текст | личное | поле ввода, при включённой очистке сервер пользователя |
| Ключ API | секрет | Android Keystore, заголовок `Authorization` |
| Адрес и модель | несекретные настройки | `SharedPreferences` |
| Ответ модели | недоверенный текст | поле ввода после очистки |

Границы доверия:

1. Приложение и сервер пользователя. Сервер недоверенный: ответ может быть
   обрезанным, пустым, с ошибкой или с посторонним текстом.
2. Приложение и Android Keystore. Ключ шифрования не экспортируется.
3. Приложение и поле ввода в чужом приложении. Поле недоверенное: оно может
   смениться, закрыться или потерять фокус.

## Права

Добавлено одно разрешение: `android.permission.INTERNET`. Оно нужно только
для очистки. Разрешение `RECORD_AUDIO` было раньше.

Новых экспортируемых компонентов нет. Существующие экспортируемые
компоненты (`MainActivity`, `RecognizeActivity`, `TranscribeFileActivity`,
`VoiceRecognitionService`, `RustInputMethodService`) защищены системными
разрешениями или являются точками входа, как и до задачи.

## Зависимости и лицензии

Новых runtime-зависимостей нет. Добавлены только тестовые:
JUnit 4.13.2 (EPL 1.0) и `org.json:json:20240303` (Public Domain). В APK они
не попадают. Шифрование сделано на `Android Keystore` без
`androidx.security:security-crypto`.

## Секреты и журналы

- Ключ хранится как AES/GCM 256 шифртекст в приватных `SharedPreferences`,
  ключ шифрования в Keystore, алиас
  `offline_voice_input_post_processing_key_v1`.
- При нечитаемом шифртексте (сброс блокировки, восстановление из копии)
  запись удаляется, пользователь вводит ключ заново.
- Ключ и текст не журналируются. В новом коде есть три записи в журнал:
  непредвиденная ошибка обработки, ошибка сохранения ключа и сообщение об
  удалении нечитаемого ключа. Значения ключа и текста в них не передаются.
- Ключ уходит только в заголовке `Authorization: Bearer` на адрес, который
  ввёл пользователь. Переадресация отключена, поэтому ключ не может уйти на
  другой хост через 30x.

## Негативные сценарии

| Сценарий | Поведение |
|---|---|
| Сервер недоступен | исходный текст, сообщение об ошибке |
| Тайм-аут 20 с | соединение разрывается, исходный текст |
| HTTP 401/403/404/5xx | исходный текст, короткая причина |
| Ответ больше 1 МБ | ошибка, исходный текст |
| `finish_reason: length` | ошибка, исходный текст |
| Пустой ответ или только междометия | ничего не вставляется, «Речь не распознана» |
| Смена поля во время запроса | текст не вставляется в другое поле |
| Отмена во время запроса | соединение разрывается, результат отбрасывается |
| Новая диктовка | старый результат становится недействительным |
| Адрес `http://` | предупреждение об отсутствии шифрования |
| Ответ содержит управляющие символы | удаляются невидимые символы, текст обрезается по краям |

## Инъекции и подмена

- Инструкция формируется на телефоне, распознанный текст подставляется
  в `${output}`. Пользователь может изменить инструкцию сам.
- Диктовка может содержать фразу, похожую на команду. Модель может её
  выполнить. Это остаточный риск: результат всё равно попадает только
  в текстовое поле и не исполняется.
- Ответ сервера не исполняется и не разбирается как разметка. Он вставляется
  как обычный текст.

## Проверки

| Проверка | Результат |
|---|---|
| Поиск секретов по дереву (`sk-`, `Bearer`, `api_key`) | совпадений нет, кроме маски `sk-••••••4f2a` в макете |
| Новые runtime-зависимости | нет, только `testImplementation` |
| Переадресация HTTP | отключена в коде |
| Ограничение ответа | 1 МБ |
| Журналирование ключа и текста | не найдено |
| Android lint | 7 ошибок, все в старых файлах; новых в постобработке нет |
| JVM-тесты | 21 тест, включая тайм-аут, отмену, обрезку, ошибки сервера |

SAST и SCA отдельными инструментами не запускались. Это ограничение
записано явно, а не выдано за проверку.

## Остаточные риски

1. `usesCleartextTraffic="true"` разрешает открытый трафик всему приложению.
   Нужен для локальных серверов. При выходе в интернет обязателен HTTPS.
   Компенсация: предупреждение в интерфейсе, других сетевых вызовов нет.
2. Ключ передаётся по `http://`, если пользователь сам выбрал такой адрес.
3. Модель может выполнить инструкцию из диктовки вместо редактирования.
4. Определение поля эвристическое. При сомнении текст не вставляется, но
   пользователю придётся повторить диктовку.
5. Резервное копирование приложения может скопировать шифртекст ключа.
   Без Keystore устройства он бесполезен, но сам факт копии остаётся.
6. На реальном устройстве поведение не проверялось.

## Блокирующие вопросы

Нет. Пункт 1 требует явного принятия риска владельцем, он записан в
Product Brief и в этом экране. Публикация не планируется, поэтому
требования магазина приложений к cleartext не применяются.
