# Дизайн OVI-003: выбор модели из списка

## Граница дизайна

Меняется только карточка «Очистка текста» на главном экране. Новых
экранов, навигации и тем нет. Визуальный язык остаётся прежним: Material 3,
существующие поля и кнопки.

## Элементы

1. Поле модели остаётся текстовым и редактируемым.
2. Справа от поля, в одной строке, появляется текстовая кнопка «Из списка».
   Высота касания 48 dp, название кнопки совпадает с её текстом, поэтому
   отдельная подпись для чтения с экрана не нужна. Полное действие
   поясняется в строке состояния и в заголовке окна.
3. Пока идёт запрос, кнопка остаётся доступной и меняет текст на
   «Отмена». Нажатие отменяет запрос, возвращает текст «Из списка» и
   прежнюю строку состояния. В строке состояния во время запроса
   показано «Запрашиваю список моделей…».
4. Окно выбора: заголовок «Модели сервера», поле фильтра, список,
   кнопка «Отмена». Фильтр ищет вхождение подстроки в имя модели без
   учёта регистра, включая середину имени, `/` и дефис. Пункты показывают
   идентификатор модели.
5. Если сохранённая модель не найдена в ответе, первой строкой идёт
   «Текущая: <имя>» и выбор этой строки ничего не меняет.

## Состояния

| Состояние | Что видит пользователь |
|---|---|
| Адрес пустой или без схемы | ошибка у поля адреса, запрос не уходит |
| Ключ отклонён при сохранении | ошибка у поля ключа, запрос не уходит |
| Запрос идёт | кнопка «Отмена», строка состояния о загрузке |
| Список получен | окно с фильтром, список отсортирован |
| Одна модель | поле заполняется сразу, окно не открывается |
| Пустой список | сообщение «Сервер вернул пустой список», ручной ввод |
| HTTP 401 или 403 | сообщение о ключе, ручной ввод |
| HTTP 404 | сообщение «сервер не поддерживает список моделей» |
| Ответ не JSON | сообщение «не удалось разобрать ответ» |
| Тайм-аут или сеть | короткое сообщение, ручной ввод |

## Поведение при ошибках

Ни одна ошибка не стирает адрес, ключ или текущую модель. Окно выбора
закрывается только по выбору пункта или по кнопке «Отмена». После ошибки
кнопка снова доступна с текстом «Из списка».

## Уход с экрана

- Экран перестал быть видимым (`onStop`): запрос отменяется, кнопка
  возвращается к тексту «Из списка», результат не показывается.
- Экран уничтожается (`onDestroy`): запрос отменяется, повторная отмена
  безопасна.
- Возврат на экран показывает обычное состояние, без окна и без
  применённой модели отменённого запроса.

## Техническая схема

- `PostProcessingLogic.buildModelsUrl(endpoint)`: те же правила, что у
  `buildChatCompletionsUrl`, но с заменой `/chat/completions` на `/models`.
- `PostProcessingLogic.parseModelIds(json)`: разбор четырёх форм ответа,
  обрезка пробелов, отбрасывание пустых, удаление точных повторов,
  сортировка без учёта регистра, ограничение 500 элементов и 200 символов
  на имя. Имена, различающиеся только регистром, остаются: сервер мог
  завести их как разные модели.
- `PostProcessingLogic.matchesModelQuery(id, query)`: поиск подстроки без
  учёта регистра для фильтра в окне выбора.
- `OpenAiCompatibleClient.listModels(...)`: `GET`, `Accept: application/json`,
  тот же заголовок `Authorization`, отключённые переадресации, предел
  ответа 1 МиБ, те же короткие ошибки.
- `PostProcessor.listModels(...)`: выполнение вне главного потока,
  сторожевой таймер и отмена, как у очистки.
- `MainActivity`: привязка кнопки, окно с фильтром, сохранение выбора.
  Во время запроса кнопка работает как «Отмена». Запрос отменяется
  в `onStop` и повторно в `onDestroy`.

## Доступность

- У кнопки есть понятный текст, он же служит именем для чтения с экрана.
- Текст кнопки меняется на «Отмена» во время запроса, поэтому TalkBack
  называет доступное действие, а не недоступное.
- Список доступен с клавиатуры и через TalkBack как обычный список.
- Фильтр не мешает выбрать пункт касанием.
- Текст ошибок короткий и не полагается только на цвет.

## Что не проектируется

- Отдельный экран управления моделями.
- Кэш списка между запусками.
- Автоматический запрос при открытии экрана.
- Проверка каждой модели запросом очистки.
