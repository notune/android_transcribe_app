# Product Brief: OVI-001

## Задача и аудитория

Пользователь: человек, который диктует текст на русском в любом приложении
через клавиатуру Offline Voice Input, часто без интернета или без доверия
к облаку. Сегодня приложение распознаёт речь полностью на телефоне, но
качество русской расшифровки и пунктуация зависят от текущей связки
`transcribe.cpp` и Parakeet. В тексте остаются оговорки, повторы, неверная
пунктуация и искажённые имена.

Задача состоит из двух связанных частей:

1. Перевести распознавание на GigaAM v3 (русский, MIT), локально на телефоне.
2. Добавить необязательную очистку текста языковой моделью по примеру Handy,
   не отправляя аудио на сервер.

Почему вместе: очистка получает на вход расшифровку. Если менять движок
распознавания и не проверить связку с очисткой, качество итогового текста
нельзя оценить.

## Результат

Первая версия считается полезной, если одновременно выполняются условия:

1. Аудио никогда не уходит за пределы телефона. На сервер отправляется
   только распознанный текст и только при включённой очистке.
2. Распознавание идёт локально на GigaAM v3 и работает без сети.
3. GigaAM даёт пунктуацию и нормализацию текста (вариант `e2e`).
4. Очистка выключена по умолчанию. Без настройки приложение работает как
   раньше, только с новым движком распознавания.
5. При ошибке сети, тайм-ауте, ошибке HTTP или пустом ответе вставляется
   исходная расшифровка, а причина показывается отдельно. Текст ошибки
   никогда не попадает в поле.
6. Отмена, смена поля и новая диктовка не приводят к повторной вставке или
   вставке устаревшего результата.
7. Пользователь может проверить связь с сервером до первой диктовки.
8. Ключ не хранится в открытом виде и не попадает в журналы.
9. Работает во всех трёх путях ввода: клавиатура, панель `RecognizeActivity`,
   системный `VoiceRecognitionService`.

## Сценарии и границы

Основные сценарии:

- обычная диктовка на русском без сети;
- диктовка с пунктуацией и числами;
- длинная диктовка и разбиение на части;
- включение очистки, ввод адреса, модели и ключа, проверка связи;
- диктовка с очисткой и вставкой очищенного текста;
- отмена во время записи, распознавания и очистки;
- смена поля во время запроса;
- недоступный сервер и возврат к исходному тексту.

Что не входит в эту задачу:

- весь блок визуального дизайна: макеты, выбор направления, визуальное
  оформление (пользователь исключил 26.11.2026);
- другие языки и мультиязычная модель GigaAM;
- распознавание эмоций, диаризация, тайм-коды слов;
- дообучение модели;
- импорт сторонних GGUF и экран выбора модели;
- сборка `fdroid` без встроенной модели;
- способ обновления модели на телефоне;
- публикация и выпуск версии.

## Модель распознавания

| Что | Решение |
|---|---|
| Модель | GigaAM v3 `e2e_rnnt`, квантование Q6_K, GGUF |
| Файл | `gigaam-v3-e2e-rnnt-Q6_K.gguf` |
| Источник | `handy-computer/gigaam-v3-e2e-rnnt-gguf`, ревизия `3efd5b3` |
| SHA-256 | `1ef0f771d9ab0b0675c45ce67a3e5b79ac7497fe35ebb08a51704c4ee423edce` |
| Размер | 227 953 952 байта, около 228 МБ |
| Язык | русский, без перевода |
| Лицензия | MIT |
| Где работает | только на телефоне |
| Рантайм | существующий `transcribe.cpp` 0.4.0, архитектура `gigaam` |
| Пунктуация | есть, вместе с регистром |
| WER FLEURS ru | 5.37 процента по данным автора конвертации |
| Доставка | скачивается при сборке `standard`, SHA-256 проверяется |

Открытые решения, которые снимаются этой задачей:

- отдельный ONNX Runtime не нужен, `transcribe.cpp` уже умеет GigaAM;
- вариант модели выбран: `e2e_rnnt` Q6_K;
- доставка выбрана: встроенная модель в `standard`, скачивание в браузере
  для `fdroid`;
- `transcribe.cpp` остаётся движком, Parakeet остаётся доступным как
  дополнительная модель для других языков.

## Дизайн

Визуальный дизайн в задачу не входит. Пользователь 26.11.2026 потребовал
убрать весь блок визуального дизайна из заданий. Это значит:

- макеты не утверждаются, не дорабатываются и не переносятся в код;
- визуальное направление не выбирается;
- оценка внешнего вида не является критерием приёмки этой задачи.

Изменения разметки в этой задаче это подключение уже существующих
компонентов Material 3 и текстов к новым настройкам. Новый визуальный язык
не создаётся. Поэтому отдельного согласования дизайна нет: есть только
подтверждение этой границы в Product Brief.

## Данные и безопасность

| Данные | Где | Граница |
|---|---|---|
| Аудио | телефон | не покидает устройство |
| Модель распознавания | телефон | файл в приватном каталоге, проверка SHA-256 |
| Распознанный текст | телефон, затем сервер пользователя | на сервер только при включённой очистке |
| Ключ API | телефон | Android Keystore, AES/GCM 256 |
| Настройки адреса и модели | телефон | обычные `SharedPreferences` |
| История диктовок | не хранится | намеренно |

Сервер очистки задаёт пользователь. В коде нет ни адреса, ни ключа, ни
модели. Отправка текста внешнему провайдеру требует явного включения
и предупреждения про `http://`.

Модель скачивается с указанного источника и проверяется по SHA-256. Если
проверка не прошла, движок не запускается и приложение остаётся на прежнем
движке, пока пользователь не установит модель заново.

## Существенные допущения и альтернативы

- Формат запроса очистки повторяет legacy-режим Handy: инструкция
  с `${output}` и одно сообщение `role: user` в `/chat/completions`.
- Модель очистки по умолчанию `cowork-hard`; ключ выдаётся для её
  провайдера. Базовый адрес вводит пользователь, в коде его нет.
- GigaAM выбран пользователем 24.11.2026 как единственная целевая модель
  распознавания. Запасного пути по качеству нет: это принятый риск.
- Рассматривались: оставить Parakeet (отклонено), облачное распознавание
  (отклонено, аудио уходит), локальная языковая модель на телефоне для
  очистки (отклонено, размер и скорость).
- Тайм-аут очистки 20 секунд выбран как компромисс между медленной моделью
  и ожиданием пользователя.
- `http://` для очистки разрешён для локальных серверов, риск показан
  в интерфейсе.

## Известные задачи, которые остаются за рамками

1. Проверка на реальном телефоне: установка, микрофон, шум, задержка,
   память, расход батареи, смена поля, авиарежим.
2. Прогон `tests/run_post_processing_cases.py` на сервере и модели
   пользователя.
3. Решение по сборке `fdroid`: без импорта модели и без встроенной модели
   она теряет смысл.
4. Способ обновления модели GigaAM после первого релиза.

## Граница поручения

Пользователь попросил прогнать полный цикл AEK. Это разрешение на этапы
discovery, design, planning, implementation, verification, release и done
в объёме этой задачи. Этап `design` фиксирует только границу: визуальный
дизайн вне объёма. Публикация, тег и выпуск не разрешены и не входят
в цикл.

Если реализация GigaAM не сможет быть проверена в этой среде, цикл
останавливается на verification с явной пометкой «не проверено на
устройстве», а не выдаётся за готовый результат.
