# Architecture Simplification Decision: OVI-001

## Контекст и проверенные факты

- Приложение уже распознаёт речь локально и отдаёт текст в поле через три
  пути: `RustInputMethodService`, `RecognizeActivity`, `VoiceRecognitionService`.
- В проекте есть `org.json` и `HttpURLConnection`, отдельных сетевых
  библиотек нет.
- Минимальная версия Android и текущие зависимости заданы в
  `app/build.gradle.kts`; новых runtime-зависимостей не добавлялось.
- Legacy-режим Handy отправляет инструкцию с `${output}` и одно сообщение
  `role: user` в `/chat/completions`. Это проверено по исходникам Handy и
  сохранено в `prompts/handy-post-processing-ru.txt`.

## Что можем не делать

- Свой HTTP-стек: хватает `HttpURLConnection`.
- Шифрование настроек через `androidx.security:security-crypto`: библиотека
  в статусе deprecated, хватает прямого Android Keystore.
- Очередь, `WorkManager`, повторные попытки: пользователь ждёт один ответ,
  повтор только запутает вставку.
- Собственный сервер, прокси, телеметрию: сервер задаёт пользователь.
- Хранение истории диктовок: повышает риск утечки и не нужно для первой
  версии.
- Отдельный движок распознавания, ONNX Runtime и импорт GGUF: GigaAM v3
  уже есть в `transcribe.cpp` как архитектура `gigaam`, поэтому достаточно
  заменить файл модели и ссылки на неё.
- Отдельный экран настроек очистки: хватает карточки на главном экране.

## Что можно взять готовым

- `org.json` для сборки и разбора JSON.
- `HttpURLConnection` для POST и тайм-аутов.
- `Android Keystore` с AES/GCM 256 для ключа.
- `SharedPreferences` для адреса, модели, флага и инструкции.
- Material 3 для карточки, полей, переключателя и кнопок.
- JUnit 4 и `org.json` только для JVM-тестов.

## Какие компоненты можно упростить

| Компонент | Решение |
|---|---|
| `PostProcessingLogic` | чистая логика без Android, поэтому проверяется на JVM |
| `OpenAiCompatibleClient` | один статический метод, без интерфейсов и фабрик |
| `SecretStore` | один класс, AES/GCM, без репозиториев и слоёв |
| `EditorTarget` | снимок поля для проверки, что результат не уйдёт в другое поле |
| `PostProcessor` | один `ExecutorService` на процесс, отмена через разрыв соединения |

Проверка `EditorTarget` намеренно эвристическая. Полное определение поля
в веб-вью и Compose невозможно, поэтому при сомнении текст не вставляется.

## Библиотеки: версии, совместимость, лицензии

Новых runtime-библиотек нет. Модель распознавания GigaAM v3 e2e RNNT Q6_K
это GGUF, который понимает уже подключённый `transcribe.cpp` 0.4.0:
в `transcribe-cpp-sys` есть `src/arch/gigaam` с вариантами `e2e_rnnt`,
`e2e_ctc`, `rnnt`, `ctc`. Отдельный ONNX Runtime не нужен.

Тестовые зависимости: JUnit 4.13.2 (Eclipse Public License 1.0) и
`org.json:json:20240303` (Public Domain). Обе только для JVM-тестов и в APK
не попадают. Модель GigaAM распространяется по лицензии MIT.

## Контракты и риски

- Контракт с сервером: OpenAI-совместимый `POST /v1/chat/completions`.
  Ответ читается из `choices[0].message.content`.
- `finish_reason: length` считается ошибкой, чтобы не вставить обрезанный
  текст.
- Переадресация отключена, чтобы ключ не ушёл на другой хост.
- `usesCleartextTraffic="true"` разрешён на уровне приложения. Это самый
  простой способ поддержать локальные `http://` серверы, но он разрешает
  открытый трафик всему приложению. Компенсация: предупреждение в интерфейсе
  и отсутствие других сетевых вызовов, кроме этого клиента. Риск принят
  явно, при выходе за пределы локальной сети нужен HTTPS.
- Тайм-аут 20 секунд общий для соединения и чтения.

## Принятое минимально достаточное решение

Три класса вокруг одного запроса плюс снимок поля. Никаких слоёв,
репозиториев, DI и фоновых служб. Вся логика, которую можно проверить без
Android, вынесена в `PostProcessingLogic` и покрыта JVM-тестами.

## Влияние на UX / DX / AX

- UX: очистка необязательна, состояние видно в существующей строке,
  ошибка не попадает в поле, отмена доступна.
- DX: логика отделена от Android и тестируется на JVM без эмулятора.
- AX: у задачи есть явные границы, известные блокеры и свидетельства,
  привязанные к SHA.

## Непроверенные допущения

- Что `cowork-hard` достаточно хорошо выполняет инструкцию Handy.
- Что 20 секунд хватает типовому серверу пользователя.
- Что эвристика `EditorTarget` не мешает в популярных приложениях.
- Что `usesCleartextTraffic` не создаёт проблем при проверке в магазине
  приложений.
- Что поведение на реальном телефоне совпадёт с JVM-тестами.
