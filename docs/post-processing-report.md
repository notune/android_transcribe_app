# Отчёт: необязательная постобработка голосового ввода

## Кратко

В ветке `feature/handy-post-processing` добавлена необязательная очистка
распознанного текста через OpenAI-совместимый сервер. Локальное распознавание
и интерфейс клавиатуры сохранены. Аудио на сервер не отправляется, уходит
только текст. По умолчанию очистка выключена. Встроенная модель распознавания
заменена с Parakeet на GigaAM v3 e2e RNNT Q6_K: она даёт русский текст
с пунктуацией и регистром.

Код Android изменён и собирается. На реальном телефоне приложение ещё не
запускалось: в окружении сборки нет телефона, пользовательского сервера и
ключа. Поэтому ниже отдельно указано, что проверено фактически, а что нужно
проверить вручную.

## Что реализовано

### Настройки

- Карточка «Очистка текста (необязательно)» на главном экране.
- Переключатель очистки, адрес сервера, имя модели, ключ API.
- Редактируемая инструкция с заполнителем `${output}` и кнопкой возврата
  встроенного текста.
- Кнопка «Проверить связь»: отправляет синтетическую фразу и показывает
  исходный и очищенный текст либо ошибку.
- Предупреждение при адресе `http://`.
- По умолчанию поля пустые. Никакой сервер, модель или ключ не зашиты
  в приложение.

Ключ хранится не в обычных настройках, а в `SharedPreferences` в зашифрованном
виде. Шифрование выполняет Android Keystore, алгоритм AES/GCM, ключ устройства
не экспортируется. При смене блокировки или восстановлении из резервной копии
нечитаемый ключ удаляется, и пользователь может ввести новый.

### Сетевой запрос

- Отдельный Java-клиент `OpenAiCompatibleClient`, без новых зависимостей.
- Адрес приводится к виду `/v1/chat/completions`, если пользователь не указал
  полный путь.
- Инструкция заполняется распознанным текстом и отправляется одним сообщением
  `role: user`. Формат совместим с legacy-режимом Handy.
- Нет `response_format`, `temperature`, `max_tokens` и полей reasoning:
  локальные серверы и шлюзы понимают их по-разному.
- Тайм-аут 20 секунд, отдельный сторожевой таймер разрывает соединение.
- Ответ ограничен 1 МБ. Ответ с `finish_reason: length` считается ошибкой,
  чтобы не вставить обрезанную диктовку.
- Переадресация отключена, чтобы ключ не ушёл на другой хост.
- Ключ и текст не журналируются.

### Надёжность и отмена

- Каждая диктовка получает номер. Новая запись, отмена и скрытие клавиатуры
  с включённой настройкой «останавливать при скрытии» делают старый результат
  недействительным.
- Результат привязан к полю, в котором началась диктовка: пакет, id поля, тип
  ввода, имя поля и подсказка. При смене поля текст не вставляется в новое.
- Если поле временно потеряло фокус, текст придерживается и вставляется при
  возврате в то же поле. В другое поле он не попадёт.
- Кнопка записи остаётся недоступной, пока распознавание или очистка не
  завершились, чтобы новая запись не потеряла предыдущий текст.
- При ошибке сети, тайм-ауте, ошибке HTTP, пустом или обрезанном ответе
  вставляется исходная расшифровка, а причина показывается отдельно.
- Если модель вернула пустой ответ на междометия или просто повторила их,
  ничего не вставляется и показывается «Речь не распознана».

### Три пути ввода

Очистка подключена во всех местах, где приложение отдаёт текст:

1. Клавиатура `RustInputMethodService`.
2. Панель `RecognizeActivity` для `RecognizeIntent`.
3. Системный `VoiceRecognitionService` для других клавиатур.

Везде сохраняется исходный текст для отката и отменяется запоздавший результат.

### Распознавание GigaAM

Встроенная модель заменена на `gigaam-v3-e2e-rnnt-Q6_K.gguf`, 228 МБ,
лицензия MIT. Новый рантайм не добавлялся: `transcribe.cpp` 0.4.0 уже
содержит архитектуру `gigaam`, поэтому изменились файл модели, ссылка
для скачивания и подписи в интерфейсе.

- Модель скачивается при сборке `standard` и проверяется по SHA-256
  `1ef0f771d9ab0b0675c45ce67a3e5b79ac7497fe35ebb08a51704c4ee423edce`.
- Сборка `fdroid` по-прежнему без встроенной модели: она предлагает скачать
  GigaAM в браузере.
- Parakeet и другие GGUF остаются доступными для других языков.
- Модель понимает только русский. Языковая подсказка для неё игнорируется.

Проверка модели на хосте: тот же `transcribe-cpp 0.4.0`, файл с тем же
SHA-256, русская фраза, синтезированная голосом Milena. Получено:
«Привет. Это проверка распознавания русской речи. Запишите встречу на
четверг в 16:30 и не забудьте про отчёт.» Пунктуация, регистр и число
сохранены. Лог: `.agentic-kit/evidence/OVI-001/model-smoke.log`.
Это проверка на macOS, не на телефоне: задержка и память телефона остаются
неизмеренными.

### Тесты и документация

- 27 JVM-тестов: разбор адреса и JSON, подстановка `${output}`, разбор ответа,

- Скрипт `tests/run_post_processing_cases.py` для прогона синтетических

### Исправления после независимой проверки

Проверяющий `qa-1` нашёл четыре важные ошибки. Они исправлены в коде:

1. `SecretStore` больше не передаёт собственный IV: шифр Keystore сам
   формирует IV, а длина и значение IV сохраняются вместе с шифртекстом.
   Ошибка записи возвращается вызывающему коду и показывается у поля ключа.
2. `EditorTarget` получил признак сильной идентичности. Если у поля нет
   ни view id, ни имени, дополнительно требуется неизменный сеанс ввода:
   номер сеанса растёт при каждом `onStartInput`, а диктовка запоминает
   свой. Запоздалый результат не вставляется в другое поле с такой же
   `EditorInfo`.
3. `RustInputMethodService.onWindowHidden()` теперь отменяет диктовку при
   `stop_on_hide` и в промежутке между остановкой записи и готовым
   распознанным текстом, а не только во время сетевой очистки.
4. `OpenAiCompatibleClient` проверяет отмену сразу после `onOpen` и ещё раз
   перед записью тела. Отмена до открытия потока не отправляет текст.
   Добавлен JVM-тест: сервер не получает ни одного запроса.

Исправления 2 и 3 проверены чтением кода, без запуска на Android. Для
исправления 4 есть автоматический тест на loopback-сервере.

Второй круг проверки нашёл ещё три важные ошибки, они тоже исправлены:

5. `EditorTarget`: `View.NO_ID` (-1) больше не считается стабильным
   идентификатором поля. Для проверки добавлен JVM-тест на 0, -1 и обычный
   положительный id.
6. `RecognizeActivity`: закрытие панели и `onStop` отменяют диктовку и в
   промежутке между остановкой записи и готовым текстом, поэтому поздний
   колбэк не запускает сетевой запрос и не доставляет результат.
7. `VoiceRecognitionService`: проверка колбэка и публикация задачи очистки
   выполняются в главном потоке, там же, где `end()`. Отмена сессии больше
   не может оставить работающий запрос, который никто не отменит.

Третий круг нашёл ещё одну важную ошибку, она исправлена:

8. `RustInputMethodService`: номер диктовки теперь передаётся в native-код
   при старте записи и возвращается вместе с расшифровкой. Поздний текст
   отменённой записи сверяется с этим номером до изменения состояния новой
   диктовки и отбрасывается. Если расшифровка не дала текста, приходит
   отдельный сигнал завершения с тем же номером, поэтому ожидание
   снимается только у своей диктовки, а не у той, что идёт сейчас.

Исправления 5-8 проверены чтением кода, сборкой native-библиотеки и
JVM-тестами. 6-8 требуют проверки на устройстве.

Четвёртый круг нашёл ещё две важные ошибки, они исправлены:

9. `RustInputMethodService`: отклонённый поздний текст больше не сбрасывает
   состояние текущей записи. Раньше отказ вызывал `updateRecordButtonUI(false)`
   и помечал микрофон остановленным, хотя новая запись продолжалась.
10. `app/proguard-rules.pro`: сохранены новые JNI-колбэки
    `onTextTranscribed(String, int)` и `onTranscriptionFinished(int)`, а также
    прежний `onTextTranscribed(String)`. Проверено сборкой
    `:app:minifyFdroidReleaseWithR8`: в dex оба новых имени есть, в
    `usage.txt` они отсутствуют.

Исправление 9 проверено чтением кода, 10 проверено оптимизированной сборкой.
Оба ещё требуют прогона на устройстве.

Пятый круг нашёл ещё одну важную ошибку, она исправлена:

11. `OpenAiCompatibleClient`: ключ с управляющими символами отклоняется до
    установки заголовка, потому что исключение HTTP-слоя повторяет значение
    заголовка. `PostProcessor` больше не пишет в журнал текст исключения,
    только фиксированное сообщение. `SecretStore` пишет только тип ошибки.
    Добавлены тесты: некорректный ключ даёт `invalid API key`, запрос не
    уходит, значение ключа в сообщении отсутствует.

Шестой круг уточнил проверку ключа, ошибка исправлена:

12. Ключ проверяется до `trim()`, поэтому управляющий символ на краю
    значения (в том числе один NUL) больше не удаляется молча. Такой ключ
    отклоняется с `invalid API key` и не отправляется. При сохранении
    настроек `PostProcessingSettings` проверяет исходное значение и
    показывает у поля ключа отдельное сообщение о недопустимых символах.
    Пустое значение по-прежнему означает «ключ не нужен». Тесты расширены:
    завершающий перевод строки, ведущий возврат каретки, завершающий и
    одиночный NUL, не-ASCII и пустая строка из пробелов.

### Прогон на локальной модели

Чтобы проверить не только сборку, но и сам запрос, поднимался локальный
OpenAI-совместимый сервер `llama.cpp` с моделью
`Qwen2.5-7B-Instruct-Q4_K_M`. Это не модель пользователя и не его сервер,
поэтому результат ниже является дымовой проверкой, а не доказательством
качества.

Запуск:

```
OVI_PP_ENDPOINT=http://127.0.0.1:18080/v1 \
OVI_PP_MODEL=qwen2.5-7b-instruct \
python3 tests/run_post_processing_cases.py
```

Первый прогон дал 5 из 7 по тогдашней, более мягкой проверке вопроса.
После того как проверка стала строже и добавленный ответ «четыре» тоже
считается нарушением, повторный прогон дал 2 из 7. Разница объясняется и
нестабильностью модели, и тем, что мягкая проверка пропускала добавленный
ответ.

В строгом прогоне прошли только `negation` и `numbers`. Остальные примеры
показали:

- `self-correction`: осталось «три сервера, нет, два сервера», отменённое
  количество не убрано;
- `terms`: не восстановлены `H200` и `Codex`;
- `cowork`: место встречи «коворк» превращено в продукт `Giga Cowork`,
  хотя инструкция прямо запрещает это;
- `literal-instruction`: к вопросу добавлено «равно четыре», то есть модель
  выполнила его вместо редактирования;
- `empty`: междометия возвращены как есть, а не пустой строкой.

Это ожидаемый результат для небольшой локальной модели и длинной инструкции.
Он не говорит о качестве выбранной пользователем модели и не заменяет
проверку на телефоне. Важен другой вывод: приложение не должно слепо
вставлять всё, что вернула модель. Поэтому ответ, состоящий только из
междометий, теперь отбрасывается даже тогда, когда модель их повторила.

Отдельно проверен настоящий Java-клиент, а не только Python-скрипт. Одна
синтетическая фраза отправлена через `OpenAiCompatibleClient` на тот же
сервер. Ответ разобран без ошибки, закрытый порт дал `network error`,
неизвестный путь дал `HTTP 404: File Not Found`. Это подтверждает сборку
запроса, разбор ответа и обработку ошибок, но не качество текста.

Температура в запросе не задаётся, поэтому сервер использует своё значение
по умолчанию. Два прогона одной и той же фразы могут отличаться.

## Проверка на телефоне

Пошаговая инструкция: `docs/post-processing-phone-check.md`.

Коротко:

1. Установить APK, включить клавиатуру «Offline Voice Input (тест)».
2. Заполнить адрес, модель и ключ, нажать «Проверить связь».
3. Проверить обычную диктовку, очистку, авиарежим, отмену, смену поля,
   новую диктовку, междометия и примеры из фикстур.
4. Записать модель, сервер без ключа, исходные и полученные фразы.

## Ограничения и риски

- Определение поля эвристическое. В веб-полях и Compose идентификаторы полей
  часто отсутствуют. При сомнении приложение не вставляет текст, а сообщает
  о смене поля. Это защищает от вставки не туда, но может потребовать
  повторной диктовки.
- `http://` разрешён для локальных серверов, но текст идёт без шифрования.
  Для интернета нужен HTTPS.
- Тайм-аут 20 секунд может оказаться мал для медленной модели на слабом
  сервере. Тогда вставится исходный текст.
- Тестовая сборка подписана debug и содержит модель распознавания, поэтому
  она большая и не предназначена для публикации.
- Пока установлены обе сборки, в системе могут быть два обработчика
  распознавания речи. Это может повлиять на другие клавиатуры.
- История исходного и обработанного текста не сохраняется. Для первой версии
  это сделано намеренно, чтобы не хранить личные диктовки.
- Очистка в `VoiceRecognitionService` меняет текст для сторонних клавиатур.
  Если это не нужно, её можно выключить глобально.

## Следующие шаги

1. Установить тестовую APK и пройти проверки на телефоне.
2. Прогнать `tests/run_post_processing_cases.py` на своём сервере и модели.
3. Сравнить исходные и очищенные фразы вручную, отдельно проверить отрицания,
   числа, имена и команды.
4. При необходимости изменить инструкцию или тайм-аут и пересобрать APK.
5. Решить, нужна ли ограниченная локальная история для диагностики.
