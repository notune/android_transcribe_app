# /aek_rollback

Выполняй по запросу пользователя. Учитывай согласованный объём и разрешения; не запрашивай повторно разрешение на тот же неизменившийся план. Не используй Git reset или массовое восстановление приложения.

1. Определи точную операцию по реестру и журналу обновления, её тип, целевой проект, область команд (`global` или `project`), корень окружения и резервные копии. Не угадывай область по текущему каталогу.
2. Получи **отдельный проверенный клон AEK вне целевого проекта**, зафиксируй SHA и прочитай его AGENTS.md, docs/COMPONENTS.md, docs/UPGRADE.md и docs/SHORTCUTS.md. Используй абсолютные пути к скриптам этого клона: установленный кит может быть повреждён. Отсутствие исправного установленного AEK не является основанием переустанавливать его вместо отката.
3. Для общего обновления выполни `python3 /absolute/path/to/reviewed-aek/tools/aek.py recover --target PROJECT_FROM_RECORD --id RUN_ID`. Для прежнего обновления только кита выполни `python3 /absolute/path/to/reviewed-aek/tools/aek.py rollback --target PROJECT_FROM_RECORD --id BACKUP_ID`.
4. Для отдельного обновления команд используй `python3 /absolute/path/to/reviewed-aek/tools/aek_shortcuts.py rollback --backup-id BACKUP_ID` с областью **из записи**: `--scope project --target PROJECT_FROM_RECORD` либо `--scope global --home AGENT_HOME_FROM_RECORD`. Сверь, что домашний каталог принадлежит тому окружению агента, где было выполнено обновление.
5. Покажи план, конфликты и ограничения восстановления. Не обещай атомарный откат внешних инструментов, если его нет.
6. Примени согласованный план: для `recover` и отката кита добавь `--apply --plan-id ID`; для отката команд добавь `--plan-id ID`. Изменения пользователя после обновления не перезаписывай. Проверь результат и сообщи оставшиеся действия.
