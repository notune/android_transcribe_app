# KB Curate — облегчённая онтология

Используй при **согласованном** создании, изменении или удалении инженерных документов. Не применяй массово к OpenSpec или историческим файлам.

1. Найди существующее описание по теме через GitMark или штатный поиск: предпочтительнее **обновить** правильный документ, чем создать дубликат.
2. Зафиксируй `node_type` (decision, reference, service, runbook, gotcha, guide или plan), короткие `title` и `description`, `status`, `updated`. Не требуй полей от существующих OpenSpec-файлов.
3. Добавь релевантные ссылки на действующий код или связанные решения; не генерируй несуществующие пути.
4. Если документ генерировал агент, пометь `generated`. Поле `verified` заполняется **только** при реально подтверждённой проверке. Не подделывай `human` или иной источник; при значимых правках сбрасывай старую отметку проверки.
5. Для быстро устаревающих значений добавляй `stale_after`, но не выдумывай срок актуальности. Если он не установлен, явно укажи отсутствие политики.
6. Обновляй индекс раздела `README.md` по согласию пользователя. Не редактируй `AGENTS.md`, `CLAUDE.md` или OpenSpec автоматически по правилам OntoShip.
7. Проверь ссылки и дублирование, затем обнови индекс GitMark при наличии инструмента. Не подменяй реальную документацию сгенерированным графом.

**Источник истины:** OpenSpec для требований, исходный код и подтверждённая документация для фактов, Markdown под Git — для знаний. GitMark индекс — производный. Полная необязательная онтология: https://github.com/vakovalskii/ontoship/blob/main/docs/ontology.md
