# Проверка актуальности задания

1. Прочитай действующие OpenSpec, состояние задачи AEK, план и записанный исходный коммит.
2. Перепроверь фактическое состояние затронутых файлов, изменения после исходного коммита и незакоммиченные правки.
3. Для выполненной и уже сохранённой в Git работы сравни **исходный и итоговый коммиты** (`git diff <base-sha> <result-sha> -- <paths>`); только `git diff` рабочего дерева недостаточен.
4. Сверь исполненные шаги с реальными результатами тестов, защитой границ изменений и критериями приёмки.
5. Обозначь состояние: актуально, исполнено и проверено, заблокировано, устарело, заменено или отклонено. Не принимай отчёт агента за доказательство проверки.
6. Если план устарел, предложи уточнение и получи согласование существенных изменений. Не меняй код и не назначай исполнителей.

Единый источник состояния процесса: AEK и OpenSpec, а не отдельная очередь Improve.
