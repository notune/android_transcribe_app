# PostgreSQL Best Practices

1. Подтверди наличие/выбор PostgreSQL, её версию, слой ORM, текущие миграции, требования обратной совместимости и профиль риска.
2. Изучи код, реальные схемы и существующие библиотечные возможности прежде собственных функций. Найди релевантные рекомендации Supabase Postgres Best Practices для установленной версии.
3. Перед SQL/DDL рассмотри индексы, размер таблиц, EXPLAIN/ANALYZE, RLS и роль пользователя, блокировки, транзакции, connection pooling; не делай выводы о производительности без измерений.
4. Миграции и изменение прав выполняй только в разрешённом окружении, с бэкапом/rollback и соответствующими тестами. Не выполняй произвольный SQL на продуктивной БД.
5. Проверяй планы запросов, негативные сценарии RLS, совместимость приложения и влияние на блокировки/ресурсы.
6. Отчитайся о фактических проверках, непроверенных гипотезах и оставшихся рисках.
