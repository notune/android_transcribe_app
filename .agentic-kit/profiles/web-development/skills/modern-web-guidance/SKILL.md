# Modern Web Guidance (Web Development profile)

**Триггер:** выбран профиль Web Development и требуется создание или изменение браузерного UI, форм, CSS, клиентской логики, доступности, производительности или нативных браузерных API. Для backend/infra не запускай. Этот скилл является **обёрткой для внешнего** GoogleChrome/modern-web-guidance, а не копией оригинала.

## Последовательность

1. Убедись, что работа относится к браузерному интерфейсу, а профиль выбран и разрешён. Сначала проверь имеющуюся кодовую базу, дизайн-систему и готовые библиотеки. Для **нового** React-проекта предложи shadcn/ui + Base UI + Tailwind CSS по `.agentic-kit/docs/DESIGN.md`, при необходимости сравни с Mantine. Не устанавливай автоматически и не заменяй компоненты в существующем продукте.
2. При необходимости обращения к CLI проверь разрешение пользователя на сетевую загрузку npm-пакета; используй заранее просмотренную фиксированную версию `modern-web-guidance@1.0.0` и `DISABLE_TELEMETRY=1`. Не запускай `@latest` автоматически.
3. Найди конкретное руководство коротким **обобщённым** запросом на английском из 2–5 слов, без названий внутренних проектов, клиентских данных, исходного кода и секретов. Пример:

   `DISABLE_TELEMETRY=1 npx -y modern-web-guidance@1.0.0 search "responsive data table" --skill-version 2026_11_09-5bcc021b`

4. Из полученных ID выбери только подходящие и загрузи рекомендации:

   `DISABLE_TELEMETRY=1 npx -y modern-web-guidance@1.0.0 retrieve "<guide-id>"`

   Если точная версия CLI не доступна или сеть не разрешена, зафиксируй ограничение и используй проверенные локальные источники. Не придумывай ID/тексты рекомендаций.
5. Оцени применимость: поддерживаемые браузеры, Baseline, требуемые fallback, существующие библиотеки и архитектурную простоту. Не заменяй зрелую библиотеку нативным API автоматически и не меняй согласованный UX без решения дизайнера/пользователя.
6. Для значимого интерактивного компонента до реализации согласуй действия с клавиатуры, открытие и отмену, начальный и возвращаемый фокус, подписи, ошибки и состояния. Руководствуйся `.agentic-kit/docs/DESIGN.md`, существующей дизайн-системой и OpenSpec. Статический экран не требует отдельного описания поведения.
7. При реализации используй современные API, существующие компоненты и реальные проверки клавиатуры, фокуса и доступности. Для UI требуются реальные проверки браузера через профиль `qa-playwright` или другой разрешённый подход и отчёт `visual_qa`. Скриншот не доказывает исправность взаимодействий. UI SDK от Vercel не является обязательным; новую библиотеку подключай только после отдельного согласования.
8. Если продукт предназначен для действий ИИ-агента через интерфейс, заранее согласуй разрешённые действия, данные, подтверждения и серверные проверки прав. Не подключай `createAgent`, WebMCP и другие механизмы доступа без решения по безопасности.
9. Итог: укажи применённые рекомендации, фактически выполненные тесты и не проверенные случаи. Не выдавай рекомендации за результаты тестов.

## Brownfield: общий аудит

`legacy-scan` запускается **только** когда пользователь просит общий аудит/модернизацию устаревших веб-паттернов. Он покрывает ограниченное подмножество каталога, поэтому каждую находку нужно проверить на ложные срабатывания. Не рефакторь код автоматически и не требуй «нулевого» отчёта сканера.

## Безопасность и версии

- Репозиторий: https://github.com/GoogleChrome/modern-web-guidance
- Профиль и версия: `.agentic-kit/profiles/web-development/manifest.json`
- Не устанавливай внешние зависимости в фоне; не передавай внутренние данные поисковику.
- Вызов через `npx` может впервые скачивать пакет; только с разрешения и в доверенной среде. Отключение телеметрии не заменяет проверку сетевого поведения и npm supply chain.
