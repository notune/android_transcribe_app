# Security Audit — Trail of Bits inspired workflow

1. Уточни границы, класс данных, текущие сканеры, CI, язык, риск изменений и разрешения пользователя. Не дублируй действующий pipeline без причины.
2. Подготовь план: статический анализ, уязвимости зависимостей и API sharp edges по применимости. Проверь установленный инструмент, режимы и поддерживаемые версии.
3. Изучи официальные upstream skills/инструкции в зафиксированной версии Trail of Bits. Нельзя предполагать, что упомянутые в них скрипты присутствуют в AEK.
4. Для Semgrep запроси разрешение на rulesets, объём и тип анализа; отключи телеметрию `--metrics=off` и учитывай внешние сетевые загрузки правил. Не используйте unapproved auto-rulesets.
5. Для supply-chain аудита проверь lockfiles, версионирование и покрытие экосистем; неизвестные/непроверенные зависимости не объявляй безопасными.
6. Найденное классифицируй по фактической воспроизводимости, критичности и вероятности эксплуатации; исправляй причины, а не подавляй отчёт. Проверяй регрессии.
7. Результат: подтверждённые риски, ложные срабатывания, пробелы покрытия, отчёт и согласованные исключения.

**Важно:** этот AEK skill — безопасный маршрутизатор к возможностям Trail of Bits, не установщик и не полноценный SAST/DAST движок.
