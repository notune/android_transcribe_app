# swarm-planning

**Применяет:** Orchestrator, Architect.

**Когда:** в работе больше одной задачи, есть зависимости или несколько исполнителей, либо план нужно передать другому агенту.

**Не применять:** для одной локальной правки без параллельной работы.

## Порядок работы
Нормативное описание параллельности находится в `docs/SWARM.md`; не пересказывай его здесь.

1. Построй DAG: задачи, зависимости, владельцы, интерфейсы, изменяемые пути, общие ресурсы, критерии приёмки.
2. Выдели безопасные волны и отдельные worktrees. Зафиксируй, почему часть задач идёт последовательно.
3. Проверь план на исполнимость. По каждому шагу другой исполнитель называет действие, наблюдаемый результат, команду проверки и разрешённые пути. Заглушки `TBD`, `TODO`, «аналогично задаче N», «добавить тесты» недопустимы.
4. Для `lite` достаточно одной строки на шаг. Для `standard` и `critical` проверь покрытие каждого критерия приёмки.

## Результат
Краткий проверяемый артефакт, явные допущения и перечень того, что не проверено. Не утверждай, что команда или скилл фактически выполнялись, без подтверждения.
