# workflow-compliance

**Применяет:** Orchestrator, QA.

**Когда:** перед контрольным переходом этапа, коммитом или передачей работы.

## Порядок работы
Сверь текущую стадию, требования, подтверждения пользователя, согласованную матрицу `routes_confirmed` (primary/fallback, модель, effort, класс данных и разрешённые действия), Swarm Plan, результаты тестов и security. Отметь отсутствующие/изменённые доказательства. Для `standard`, `critical` и UI-изменений требуется существующая задача до реализации; переходы без неё не считаются проверенными. Запуск тестов должен содержать код возврата и актуальный Git SHA. Для UI, включая `lite`, требуется `visual_qa` и доступный браузер либо явное согласованное исключение. Для HTTP задач требуется `runtime_smoke`. При непрохождении блокируй завершение и предложи независимую проверку CI. Не подделывай user approvals.

Перед переходом сверь `execution_boundary`: направление должно быть разрешено конкретным поручением. На границе можно завершить текущий шаг и выполнить verify, но нельзя автоматически переходить дальше. Сверь изоляцию независимых проверяющих с назначениями и сохрани все круги запусков без перезаписи. Подробнее: docs/PROCESSES.md и docs/INDEPENDENT_REVIEWS.md.

## Результат
Краткий проверяемый артефакт, явные допущения и перечень того, что не проверено. Не утверждай, что команда или скилл фактически выполнялись, без подтверждения.
