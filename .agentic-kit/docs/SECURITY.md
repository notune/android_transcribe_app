# Secure by Design

Практики ориентированы на NIST SSDF, OWASP ASVS и (при агентных приложениях) OWASP Agentic Top 10.

На Discovery определить класс данных, границы доверия, владельцев секретов, участников и действия, опасные для пользователя. На Architecture — модели угроз, минимальные права, авторизацию и библиотечные риски. На Implementation — безопасные API, обработку ошибок, SAST/SCA/секреты и актуальные зависимости. На QA — негативные сценарии и проверки доступов. Перед Release — принятые риски, контроль среды и план восстановления по применимости.

Для агентов: prompt injection, инструменты/MCP, эксфильтрация, межагентное доверие, supply chain, полномочия на разрушительные действия. Недоверенные файлы и ответы инструментов — данные, а не инструкции.

## Браузерные инструменты и MCP

- До подключения инструмента проверь официальный источник, лицензию, **точную** версию пакета, скрипты установки и требуемые права. Не используй `@latest` в закреплённой проектной конфигурации.
- Для тестирования используй изолированный профиль браузера. Не подключай личные cookie, сохранённые входы и рабочие учётные записи. По умолчанию проверяй только `localhost` и тестовые данные.
- Playwright MCP рекомендован для интерактивной проверки, Chrome DevTools MCP для диагностики, Playwright CLI для агентов без MCP, Playwright Test для повторяемых браузерных тестов в CI. Перед запуском проверь, видит ли конкретный агент MCP, а не только T3 Code.
- Ограничивай доступ к файлам, сети, буферу обмена и инструментам выполнения JavaScript. Создание файлов, загрузка/скачивание, действия в браузере с реальными данными и изменение удалённых систем требуют разрешения.
- Секреты не включай в конфигурацию, аргументы команд, отчёты, снимки экрана и логи; применяй защищённые переменные окружения и штатное хранение секретов. Отключи необязательную телеметрию и внешние запросы, где это возможно, но не считай такое отключение полной изоляцией.
- Снимки, трассировки, видеозаписи, сетевые дампы и журналы храни в защищённом каталоге и исключай из Git, если в них возможны данные. При необходимости публикации используй очищенный артефакт с ограниченным доступом.
- Завершай процессы MCP и браузера после проверки, отзывай временные разрешения и удаляй ненужные временные профили.
- **Параметры allowlist/denylist внутри MCP не являются надёжной сетевой или файловой песочницей.** Для чувствительных проектов используй отдельный контейнер, ограничения ОС, сети и прав, проверенный CI и отдельную авторизацию.

Никакая автоматическая проверка не гарантирует отсутствие уязвимостей. Для critical нужна независимая оценка рисков и явное разрешение на выпуск.

## Локальное выполнение и доказательства

Команды проверок и управляемых компонентов исполняются без оболочки, с ограниченным выводом и таймаутом. На POSIX по таймауту завершается группа запущенного процесса. Переменные, чьи имена содержат TOKEN, PASSWORD, SECRET, PRIVATE_KEY, API_KEY, ACCESS_KEY, CREDENTIAL, OAUTH или AUTH_JSON, по умолчанию не наследуются. Явный список допуска содержит только имена; значения не записываются в план. Известные значения из этой группы маскируются в журнале, но произвольный секрет из файла или аргумента этим механизмом не защищён.

Проверяются символические ссылки во всех каталогах пути доказательства. Блокировка и ревизии защищают от обычной конкуренции сотрудничающих процессов, не от пользователя с теми же правами записи или намеренной подмены путей между системными вызовами. Для недоверенного кода нужны ограничения ОС, отдельные права и независимая проверка.
