Сама git diff --check затем успешно выполнена отдельно и проверяющим; failed-попытка не удалялась и не выдаётся за успешную запись.

## Ограничения и версия

- Python проверяет согласованность локальных импортированных наблюдений, но не обращается к MCP для удостоверения их подлинности. Локальный агент с правом записи может подделать согласованный набор файлов и состояние задачи.
- Во всех перечисленных реальных запусках requested model была `gpt-6.1-sol`, а executedModel возвращён как null. Фактически обслужившая запрос модель отдельно не подтверждена.
- Защищённый CI для удостоверения независимых проверок, другие провайдеры и полная изоляция файловой системы не подтверждены. Обычный CI репозитория выполняет тесты и не удостоверяет происхождение MCP-наблюдений.
- Status/resume используют общий git.dirty и сравнение base_commit с HEAD для source_changed; verify исключает служебные журналы. На SHIPPING-001 получены dirty=true и source_changed=true при чистых отслеживаемых исходниках и успешном verify. Эта неоднозначность не исправлена; [руководство](../INDEPENDENT_REVIEWS.md) объясняет разницу.
- Версия `2.1.0-rc.1` сохранена по [правилам версионирования](../VERSIONING.md). Коммиты, лабораторная приёмка и PR не являются выпуском; тег и Release не создаются.
