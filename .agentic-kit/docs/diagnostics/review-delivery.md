# Исправление поставки независимых проверок

Исходный коммит: `0161ced313ee1ca16add72ab6e95d3a41e9319c5`.

`tools/aek_reviews.py` присутствует в Git-дереве исходного коммита (blob `89edbabcd49f27dcd86df0375e0948bfd90e9b05`) и в чистой рабочей копии. Модуль загружается из `tools/aek.py` через `load_helper` в `review_status` и обработчике `review`. Через `review_status` он нужен также `resume`, `status`, `process_view`, переходам и `verify`. Других производственных импортирующих модулей нет; тесты `test_reviews.py` загружают его непосредственно.

В `FILES` контроллера модуль отсутствовал. `source_files` берёт только явные файлы и содержимое перечисленных папок; папки tools в FOLDERS нет. Установка вызывает source_files в aek_install.prepare, обновление вызывает тот же источник через aek_upgrade.source_map. Поэтому модуль не попадал ни в комплект, ни в манифест, ни в source_identity. Чистый Git SHA подтверждал идентичность исходника, но не полноту выбранного состава поставки.

`doctor` сверял только managed_files и managed_skills манифеста. Пропущенного файла не было в перечне ожидаемых, поэтому отсутствие не считалось ошибкой. Снимок окружения повторял проверку согласованности фактически поставленных файлов. Проверка source-correspondence старой лаборатории сравнивала 124 управляемых файла, а не полноту исполняемых зависимостей. Проверки подготовки включали environment, doctor, activation, shortcuts и четыре теста shipping, но не исполнение standard из установленного комплекта. Прежние CLI-тесты запускали tools/aek.py из исходников, где модуль присутствовал.

Исправление добавляет модуль в FILES. Doctor дополнительно проверяет наличие обязательных tools из FILES независимо от манифеста и сообщает kit_missing_required. Независимая проверка и её условия не ослаблены. Новых зависимостей, сетевых вызовов и изменений глобальных настроек нет. Версия экспериментального комплекта сохранена; исправление различается по Git SHA и source_identity, выпуск не публикуется.

Регрессия test_installed_delivery использует чистые Git-клоны зафиксированных исходников, штатную новую установку и обновление реальной прежней версии с --component kit в плане и применении. Все runtime-команды выполняются из установленного .agentic-kit в отдельном временном проекте. Resume и start-step должны работать; verify должен отказать по условиям процесса и независимой проверки, а не по ошибке загрузки. Отдельно проверяются удаление модуля, отсутствие записи в манифесте и полнота статических ссылок на вспомогательные модули. CI получает историю для воспроизводимого доступа к прежнему коммиту.

Работа последовательная: исследование, исправление, коммит, тесты поставки, новая лаборатория. Параллельные писатели не нужны: состав комплекта, диагностика и регрессия проверяют один контракт. Старая лаборатория и SHIPPING-001 не изменяются.
