# Совместимость с отдельными рабочими копиями T3

15 ноября 2026 года испытание AEK-WORKTREE-PROBE-001 в отдельной лаборатории
на исходниках AEK `33f1088d99d45b0f89af53c60f5db147e60b9804` обнаружило несовпадение
контракта: AEK требовал `isolation: worktree` в launch, а T3 возвращал путь в
`t3_thread_read.structuredContent.thread.worktreePath`. Git подтвердил отдельный
корень, отдельный git-dir, общий common-dir и регистрацию копии на том же SHA.

Исправление использует полный ответ чтения сессии и локальные команды Git при
импорте. Не вводятся новые параметры CLI, зависимости или дополнительные поля
в исходных ответах T3. Снимок Git создаёт сам импортёр; он архивируется отдельно
и связан с конкретным кругом проверки. Все сведения этого снимка относятся
к моменту импорта. Проверка использует фиксированные аргументы без shell,
ограничение времени и отключённый fsmonitor; переменные GIT_* родителя очищаются.
При назначенных отслеживаемым файлам clean/process-фильтрах импорт блокируется до status. Это исключает
запуск обработчиков из конфигурации Git; их значения не выводятся в журнал.
Git submodules также отклоняются до status, поскольку обработчики могут находиться
в их отдельных конфигурациях. Для обнаружения gitlink читается только индекс.
Неиспользуемые фильтры, включая глобальную регистрацию Git LFS в CI, не блокируют
проверку: до status назначения фильтров читаются через `git check-attr --stdin`.

Регрессия использует временный настоящий репозиторий и `git worktree add`, но
синтетические ответы T3. До исправления корректный worktree отклонялся. Проверяются
отсутствующий/относительный путь, родитель и его символьная ссылка, подкаталог,
отдельный clone, незарегистрированная копия, неверные SHA/ветка, изменения индекса
и отслеживаемых файлов, связи запуска, неполный ответ, подмена архива, повторный
импорт и восстановление после удаления копии. Это тест валидатора, не новый запуск
проверяющего через T3.

Исходное испытание было проверкой возможностей, его итог не содержал JSON-рецензию
с assignment_id/reviewed_sha/verdict. Оно не превращается в approved и не закрывает
задачу AEK. Для проверки всего процесса нужен новый реальный standard-сценарий
из установленного исправленного комплекта и остановка на verification.

Граница доверия сохраняется: локальные хеши не удостоверяют MCP, не доказывают,
что все команды исполнялись в указанной копии, и не ограничивают доступ к диску.
`executedModel: null` остаётся неизвестной фактически исполненной моделью.
