# Компоненты и единое обновление AEK

`/aek_update` ведёт через один план обновления: ядро кита, уже активированные проектные навыки, зарегистрированные группы команд и зарегистрированные внешние инструменты или навыки. Приложение и незарегистрированные инструменты автоматически под управление не попадают.

## Границы управления

- Ядро и активированные навыки обновляются существующим механизмом контрольных сумм AEK.
- Группы команд должны сначала пройти собственную регистрацию через `aek_shortcuts.py`, затем явно включаются в реестр компонентов.
- Внешний инструмент или навык регистрируется явным описанием источника, версии, области установки, каталога, управляемых файлов и проверки версии.
- `project` ограничивает каталог текущим проектом. `global` явно означает влияние на другие проекты; весь каталог и команды показаны в плане.
- Реестр `.agentic-kit/components.json` имеет `schema_version: 1`. Команды не сканируют домашний каталог в поисках инструментов и не присваивают себе чужие установки.

## Регистрация внешнего компонента

Подготовьте JSON по `examples/components-tool.example.json`. Это пример схемы, а не готовая команда установки. Замените версии и абсолютные пути по проверенной документации инструмента.

```bash
python3 /reviewed/aek/tools/aek.py components register --target /project --file /reviewed/component.json
python3 /reviewed/aek/tools/aek.py components register --target /project --file /reviewed/component.json --apply --plan-id PLAN_ID
```

Предварительный просмотр не запускает команды. При применении `version_command` должна завершиться с кодом 0 и вывести ровно `installed_version`, без баннера. Если инструмент печатает сложный вывод, используйте небольшой проверенный адаптер. `verify_command` дополнительно проверяет работоспособность после обновления и отката. `managed_paths` содержит непустой список файлов относительно `location`; их контрольные суммы защищают локальные изменения. Для многокомпонентного инструмента перечислите все файлы, которые требуется контролировать.

Команда регистрации не обновляет компонент. Она проверяет существующую версию и фиксирует явное принятие установки под управление. Повторная регистрация не заменяет уже зарегистрированный компонент с другими параметрами.

Для команды используется объект с `kind: "shortcuts"`, `adapter: "shortcuts"`, `providers: ["codex"]`. `location` указывает корень проекта либо домашний каталог окружения выбранного агента. Версия и провайдеры должны совпадать с `.aek/shortcuts-manifest.json`. Пример: `examples/components-shortcuts.example.json`.

## Подготовка обновления

Агент проверяет официальные источники и совместимость версий, затем составляет файл кандидатов по `examples/components-candidates.example.json`. Сам локальный контроллер не выполняет сетевой поиск последней версии. Если для зарегистрированного внешнего компонента кандидат не предоставлен, результат содержит `not_checked_online`; это не утверждение, что обновлений нет.

Каждый кандидат содержит точную версию, тот же источник, что в реестре, и массив аргументов `update_command`. `latest`, `main`, `master`, `next` и `*` вместо версии запрещены. Проверка версии после установки обязательна. `rollback_command` необязательна, но её отсутствие явно отражается как `rollback_available: false` до применения. При наличии скачанных локальных файлов поле `inputs` связывает абсолютные пути с SHA256. Исполняемые файлы и существующие абсолютные файловые аргументы также включаются в отпечаток плана.

```bash
# Из отдельного проверенного клона новой версии AEK, вне проекта:
python3 /reviewed/aek/tools/aek.py update --target /project --candidates /reviewed/candidates.json
# Применить ровно просмотренный план:
python3 /reviewed/aek/tools/aek.py update --target /project --candidates /reviewed/candidates.json --apply --plan-id PLAN_ID
```

По умолчанию рассматриваются ядро и все явно зарегистрированные компоненты. Ограничение: повторяемый `--component kit`, `--component my-tool`. Кандидат для незарегистрированного компонента отклоняется. Ядро применяется первым, затем группы команд, затем внешние компоненты. Новые необязательные профили AEK не активируются.

Внешние команды выполняются без shell, с закрытым stdin, ограничением времени и объёма сохраняемого вывода. При тайм-ауте завершается группа процессов там, где это поддерживает ОС. Ненулевой код, тайм-аут и усечённый вывод не проходят проверку. Это **не песочница**: проверенный исполняемый файл может обращаться к сети и изменять файлы в пределах прав пользователя. Все аргументы показываются до запуска; не помещайте секреты в JSON и аргументы. Совпадение строки `source` не удостоверяет издателя. Подлинность источника, лицензии и совместимость проверяются до подготовки рецепта. Для менеджеров пакетов закрепите точную версию также в аргументах установки.

## Переменные окружения при выполнении

Общий исполнитель для компонентов и `record --run` фильтрует унаследованные переменные с именами, похожими на секреты. Если проверенному процессу нужна такая переменная, явно разреши её **имя**, например `env_allow: ["SERVICE_TOKEN"]` в JSON компонента. Значение поступает из окружения запуска; его нельзя помещать в рецепт, аргументы или описание задачи.

Кандидат обновления может задать собственный `env_allow`; без него используется список из регистрации. Список входит в просмотренный план и применяется к проверке версии, обновлению, проверке результата и откату. Он не заменяет автоматически настройки регистрации. Для выполнения проверки задачи используется повторяемый параметр CLI:

```bash
python3 /reviewed/aek/tools/aek.py record --target /project --task APP-014 \
  --key tests --run 'python3 -m pytest' --allow-env SERVICE_TOKEN
```

Журнал политики хранит имена разрешённых и отфильтрованных переменных без значений. Из сохраняемого вывода удаляются известные исполнителю значения секретов, включая явно разрешённые. Это снижает риск случайной утечки, но не гарантирует обнаружение произвольных или преобразованных секретов. Фильтрация окружения не ограничивает права исполняемой программы.

## Фиксация и проверка окружения

`environment plan` строит инвентарь локальной установки без записи, запуска внешних программ или сетевого поиска. В снимок входят версия и `source_identity` кита, активные профили и управляемые навыки, манифесты команд, а также зарегистрированные инструменты с источником, объявленной версией, областью, каталогом и контрольными суммами управляемых файлов. Команды проекта с собственным манифестом проверяются и до их включения в реестр компонентов. Произвольные глобальные установки не сканируются.

```bash
python3 /reviewed/aek/tools/aek.py environment plan --target /project
# Зафиксировать ровно просмотренное состояние:
python3 /reviewed/aek/tools/aek.py environment apply --target /project --plan-id PLAN_ID
python3 /reviewed/aek/tools/aek.py environment check --target /project
```

`apply` записывает только `.agentic-kit/environment.lock.json`. Он не устанавливает пакеты, не восстанавливает файлы и не обновляет приложения. Повреждённые управляемые файлы и незавершённые операции нельзя принять как новую норму: сначала требуется восстановление. Изменение состояния после просмотра делает прежний `plan_id` недействительным.

`check` сравнивает текущий инвентарь с lock-файлом и возвращает `lock_present`, `matches`, `files_ready`, `passed` и `next_action`. Отсутствующий lock не считается успешной проверкой окружения. После согласованного обновления или активации профиля нужно заново просмотреть план и явно обновить lock. Снимок не включает собственный файл, поэтому повторная проверка неизменённой установки стабильна.

Это фиксация наблюдаемого состояния на текущей машине: версии внешних программ берутся из реестра (`version_probe: not_executed`), удалённые версии не проверяются (`online_versions_checked: false`). Абсолютные пути внешних компонентов привязывают снимок к окружению. Автоматического развёртывания такого же окружения на новой машине или разрешения зависимостей пока нет.

## Ошибки, продолжение и откат

После запуска сохраняется `run_id` и журнал `.agentic-kit/component-history/<run_id>/record.json`. Состояния: `prepared`, `applying`, `verified`, `failed`, `recovering`, `recovery_failed`, `rolled_back`. Версия в реестре изменяется только после успешной проверки конкретного компонента. В случае ошибки предыдущие шаги могут остаться применёнными; итог явно возвращает `state: failed`, а CLI завершается с ошибкой. Общая атомарность для внешних менеджеров пакетов не обещается.

```bash
python3 /reviewed/aek/tools/aek.py recover --target /project --id RUN_ID
python3 /reviewed/aek/tools/aek.py recover --target /project --id RUN_ID --apply --plan-id PLAN_ID
```

Восстановление идёт в обратном порядке. Для ядра и команд используется их резервная копия, для внешнего компонента его проверенный рецепт отката с проверкой исходной версии. Пользовательские изменения после обновления блокируют восстановление. Если резервная копия отсутствует, нет рецепта отката либо процесс оборвался до записи достаточных данных, требуется ручное восстановление. Нельзя выдавать такое состояние за успешный откат.

Блокировки предотвращают одновременную работу согласованных процессов AEK с одним проектом или каталогом компонента. После аварийного завершения оставшийся lock-файл требует проверки состояния процесса и журнала, а не автоматического удаления.

`doctor --target /project` читает реестр и журналы, сверяет контрольные суммы кита, компонентов и команд, включая принадлежащие проекту команды, ещё не внесённые в реестр компонентов. Самого наличия манифеста команд недостаточно. `files_ready` означает целостность проверенных управляемых файлов, а `provider_visibility: unverified` явно оставляет загрузку команд провайдером непроверенной.

Незавершённые журналы обновления и восстановления перечисляются в `pending_recovery`, обнаруженные блокировки в `operation_locks`. Они, изменённые файлы и расхождение с существующим lock окружения дают `passed: false`; `next_action` указывает следующий шаг. Отсутствие environment lock само по себе не ломает проверку прежних установок в `doctor`, но отдельный `environment check` потребует его создания. `doctor` не снимает блокировки, не исправляет файлы, не запускает внешние программы, не подтверждает доступ к моделям и не выполняет сетевой поиск.
