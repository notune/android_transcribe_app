# ADR-0001: Не включать Jev и отдельный Decision Routing в AEK

**Дата:** 2026-11-12  
**Статус:** Принято (отложено до подтверждения необходимости)  
**Область:** Orchestrator, Agent Routing, Task Triage, Workflow Enforcement

## Контекст

Рассматривалась отдельная вероятностная модель принятия решений (например, TypeSafe Jev или аналог System One) для классификации задач, выбора исполнителей, оценки риска и релевантности документов.

В AEK уже используются:
- детерминированные правила, контроль переходов и проверки разрешений;
- Harness Discovery & Assignment для согласования допустимых моделей, провайдеров и резервов;
- действующие LLM для задач, где требуется семантическая оценка;
- Orchestrator и Swarm Planning для распределения задач с учётом зависимостей.

Новая модель создала бы дополнительные зависимости, расходы, интеграции и вопросы передачи данных, а измеримого выигрыша для задач AEK пока не показано.

## Решение

**Не добавлять** Jev, AnyJev и отдельный профиль `decision-routing` в текущий AEK. Не внедрять Decision Model как обязательную роль, обязательный вызов или скрытую зависимость.

Сохраняем текущий алгоритм:
1. Проверять ограничения, разрешения, доступность моделей и зависимости задач детерминированно.
2. Для неоднозначных решений привлекать только уже согласованные и доступные LLM с контролируемыми правами.
3. Orchestrator фиксирует обоснование маршрута и использует существующие Workflow/Quality Gates.
4. Решения о безопасности, согласования пользователя, разрешения на релиз и результаты CI **никогда не подменять вероятностной оценкой модели**.

## Условия пересмотра

Возвращаться к отдельному Decision Layer только при обнаружении реальной проблемы или измеримой возможности улучшения. До включения необходимо сравнить на репрезентативных заданиях:
- детерминированные правила;
- одну из уже доступных разрешённых моделей;
- специализированную модель решений (например, Jev).

Сравнивать точность и калибровку решений, опасные ошибки маршрутизации, задержки, стоимость, работу с конфиденциальными данными и общую сложность эксплуатации. Подключение допускается только после отдельного согласования и доказанного выигрыша относительно простейшего допустимого решения.

## Последствия

Никаких новых зависимостей, CLI-адаптеров, профилей, ролей и изменений исполняемого процесса не требуется. Текущая предварительная версия **1.5.0-rc.1** остаётся прежней; этот ADR фиксирует продуктовое решение и не является функциональным релизом.
