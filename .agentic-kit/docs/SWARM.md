# Swarm by Default

1. До существенной реализации выдели проверяемые задачи и их зависимости (DAG).
2. Зафиксируй для каждой задачи владельца, входы/выходы, изменяемые пути, разделяемые ресурсы, ограничения безопасности, критерии готовности.
3. Выполняй независимые задачи в одной волне, пока не превышены лимиты моделей, API, тестовой среды и интегратора. Больше агентов не всегда быстрее.
4. Параллельные авторы кода работают в отдельных Git worktrees/ветках; разделяй тестовые базы, порты, временные директории и секреты.
5. Общие API-контракты и дизайн согласуй **до** параллельных зависимых реализаций. Дубликаты и конфликтующие изменения не запускай одновременно.
6. Единственный интегратор объединяет готовые изменения; затем запускает общие тесты, проверки безопасности и Visual QA.
7. При последовательном выполнении действительно независимых задач фиксируй причину (лимиты, конфликт ресурсов, стоимость координации, риск).

Скрипт `aek.py swarm --plan examples/swarm-plan.json` демонстрирует безопасные параллельные волны по объявленным зависимостям и ресурсам. Он **не запускает агентов** и не может обнаружить скрытые конфликты или автоматически доказать независимость задач.
