# Команды AEK

Все новые команды имеют префикс `aek_`. Старые имена без префикса не создаются и не поддерживаются как совместимые варианты.

| Команда | Назначение |
|---|---|
| `/aek_greenfield` | Создать новый проект с AEK, зарегистрировать его и открыть поток |
| `/aek_brownfield` | Подключить кит к существующему проекту |
| `/aek_update` | Обновить кит и выбранные зарегистрированные компоненты |
| `/aek_change` | Изменить приложение |
| `/aek_fix` | Исправить ошибку с проверкой причины |
| `/aek_status` | Показать состояние задач |
| `/aek_verify` | Выполнить и проверить применимые проверки |
| `/aek_resume` | Восстановить контекст и продолжить задачу |
| `/aek_audit` | Подготовить проверяемый анализ проекта |
| `/aek_doctor` | Проверить установку и окружение |
| `/aek_rollback` | Подготовить откат выбранного обновления |
| `/aek_help` | Показать команды и примеры |

`/aek_update` обновляет окружение кита. Для изменения приложения используется `/aek_change`. Все повседневные команды используют [общий процесс](DAILY_WORKFLOW.md) и состояние AEK, а не отдельные журналы по каждой команде.

Команды `/aek_change` и `/aek_fix` регистрируют основания переходов через `record --file` и отдельно переходят между этапами командой `advance`. До итогового `verify` задача должна дойти до `verification`. Принимаемые проверки `record --run` выполняются на просмотренном коммите с чистым рабочим деревом; проверки с `--allow-dirty` только диагностические. Подробные условия переходов описаны в [WORKFLOW.md](WORKFLOW.md) и [CLI.md](CLI.md).

## Провайдеры и формат имён

| Провайдер | Глобальный путь | Проектный путь | Вызов |
|---|---|---|---|
| Claude Code | `~/.claude/commands/aek_change.md` | `.claude/commands/aek_change.md` | `/aek_change` |
| OpenCode | `~/.config/opencode/commands/aek_change.md` | `.opencode/commands/aek_change.md` | `/aek_change` |
| Pi | `~/.pi/agent/prompts/aek_change.md` | `.pi/prompts/aek_change.md` | `/aek_change` |
| Codex | `~/.agents/skills/aek-change/SKILL.md` | `.agents/skills/aek-change/SKILL.md` | `$aek-change` |

В Codex переносимые навыки используют дефис: стандарт Agent Skills допускает в имени строчные буквы, цифры и дефисы. Поэтому `$aek-greenfield`, `$aek-update` и остальные имена отличаются от нативных команд с подчёркиванием. Принудительно создавать невалидные имена навыков не следует.

T3 Code показывает команды и навыки выбранного провайдера. Наличие файлов и успешный `check` не доказывают их видимость или исполнение в приложении. После изменения окружения перезапусти агентную сессию средствами T3 Code и проверь безопасный вызов `aek_help` в используемом провайдере. Проверка в реальном интерфейсе для этой поставки не выполнена.

`aek.py doctor --target /path/to/project` сверяет хеши файлов с манифестами команд. Проверяются зарегистрированные группы и собственные команды проекта, даже если их ещё нет в реестре компонентов; произвольные глобальные каталоги не сканируются. Удалённый или изменённый файл даёт `files_ready: false`. Само присутствие манифеста не считается успешной проверкой.

`files_ready: true` подтверждает только состояние управляемых файлов; `provider_visibility` остаётся `unverified`. Незавершённые операции, оставшиеся блокировки и расхождение с существующим lock окружения могут дать `passed: false` при целых файлах. `doctor` показывает диагностику и следующий шаг, не удаляя блокировки и не выполняя команды провайдера. Инвентарь можно отдельно зафиксировать и проверять через `environment plan/apply/check`, как описано в [COMPONENTS.md](COMPONENTS.md#фиксация-и-проверка-окружения).

Источники форматов: [Agent Skills](https://agentskills.io/specification), [Claude Code](https://code.claude.com/docs/en/skills), [OpenCode](https://opencode.ai/docs/commands/). В Claude Code поддерживаемый формат файлов commands позволяет сохранить запрошенное подчёркивание; имя команды берётся из имени файла.

## Установка и обновление команд

Для новых пустых проектов нужна глобальная регистрация на машине, где исполняется агент. Для одного репозитория используй проектную область. Команды выполняются из отдельного проверенного источника AEK.

```bash
python3 tools/aek_shortcuts.py plan --scope global --provider codex
# Применение конкретного просмотренного плана:
python3 tools/aek_shortcuts.py apply --scope global --provider codex --plan-id PLAN_ID
python3 tools/aek_shortcuts.py check --scope global --provider codex
```

Для проекта:

```bash
python3 tools/aek_shortcuts.py plan --scope project --target /path/to/project --provider claude
python3 tools/aek_shortcuts.py apply --scope project --target /path/to/project --provider claude --plan-id PLAN_ID
python3 tools/aek_shortcuts.py check --scope project --target /path/to/project --provider claude
```

Параметр `--provider` повторяется для нескольких провайдеров; без него выбираются все четыре. Набор должен совпадать при просмотре и применении. Порядок и повторение параметров не меняют смысл плана. Ранее полученное разрешение на тот же неизменившийся план не нужно запрашивать повторно.

При обновлении запускай те же команды из нового проверенного источника. Состояния файлов различаются явно:

- отсутствующий новый файл добавляется;
- неизменённый управляемый файл обновляется;
- совпадающий файл остаётся без записи;
- изменённый пользователем или ранее удалённый управляемый файл создаёт конфликт;
- чужой существующий файл с другим содержимым не перезаписывается.

Реестр `.aek/shortcuts-manifest.json` хранит версии и контрольные суммы по провайдерам. Для глобальной области он расположен относительно домашнего каталога, для проектной относительно проекта. Обновление одного провайдера сохраняет записи остальных. Совпадающий, но ранее неуправляемый файл автоматически не присваивается установщиком.

Предварительный просмотр не создаёт файлов. `apply` сверяет `plan_id`, использует блокировку, создаёт резервную копию и проверяет актуальность файлов перед записью. Сбой применения вызывает восстановление уже изменённых файлов. При аварийном завершении процесса журнал и оставшаяся блокировка требуют проверки, гарантии восстановления после отключения питания нет.

## Переход со старых команд

Из исходного кода удалены `greenfield`, `brownfield`, `update`. При применении установщик удаляет прежние файлы **только при полном совпадении** с контрольными суммами команд версии `2.1.0-rc.1`. Удаление отражается в плане и резервной копии.

Файлы с неизвестным или изменённым содержимым остаются пользовательскими и перечисляются в `unmanaged_legacy`. Это не создание совместимых вариантов: такие файлы требуют отдельного решения владельца. По одному только имени удаление запрещено.

## Откат команд

Результат применения содержит `backup_id`. Определи область и корень установки по реестру и журналу, не по текущему рабочему каталогу. Все восстановительные команды запускай по абсолютному пути из **отдельного проверенного клона AEK вне проекта**. Установленный кит может быть повреждён; его скрипты для восстановления не используются.

Для записи с областью `project`:

```bash
python3 /absolute/path/to/reviewed-aek/tools/aek_shortcuts.py rollback --scope project --target /path/from/record/project --backup-id BACKUP_ID
python3 /absolute/path/to/reviewed-aek/tools/aek_shortcuts.py rollback --scope project --target /path/from/record/project --backup-id BACKUP_ID --plan-id ROLLBACK_PLAN_ID
```

Для записи с областью `global`:

```bash
python3 /absolute/path/to/reviewed-aek/tools/aek_shortcuts.py rollback --scope global --home /path/from/record/agent-home --backup-id BACKUP_ID
python3 /absolute/path/to/reviewed-aek/tools/aek_shortcuts.py rollback --scope global --home /path/from/record/agent-home --backup-id BACKUP_ID --plan-id ROLLBACK_PLAN_ID
```

`--home` явно задаёт корень той машины и учётной записи агента, где выполнялась глобальная установка. Если после обновления файлы менялись, откат блокируется; пользовательские изменения не затираются.

Для общего обновления используется `aek.py recover --target PROJECT --id RUN_ID`, для прежнего обновления только кита `aek.py rollback --target PROJECT --id BACKUP_ID`. Оба скрипта также запускаются по абсолютному пути из отдельного проверенного клона. Применение просмотренного плана требует `--apply --plan-id ID`.

В общем обновлении окружения зарегистрированные группы команд обрабатываются через [реестр компонентов](COMPONENTS.md). Наличие глобальных файлов само по себе не включает их в управление проектом.

## Примеры

```text
/aek_greenfield Создать приложение для заявок
/aek_change Добавить экспорт выбранных заявок в Excel
/aek_fix При отмене редактирования теряется исходный текст
/aek_status APP-014
/aek_resume APP-014
/aek_update
```

В Codex используй соответствующее имя `$aek-change` и остальные имена с дефисом. Команды являются инструкциями для агента. Они не выдают ему дополнительных полномочий и не удостоверяют согласования пользователя.

## Наблюдение в T3 Code

13 ноября 2026 года в отдельном тестовом проекте с Codex интерфейс T3 Code показал `$aek-doctor` в списке Skills как `Repo Skill`. Это подтверждает обнаружение проектного навыка. Выполнение диагностики в приложении не подтверждено: пользователь остановил сеанс управления до отправки проверочного запроса. Это наблюдение не распространяется на другие провайдеры, все 12 команд или полный цикл изменения проекта.
