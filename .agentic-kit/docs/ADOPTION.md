# Подключение нового и существующего проекта

## Новый проект

1. Проверь разрешённую среду и получи AEK в отдельный каталог вне продукта.
2. Создай целевую папку. Выполни `inspect`, затем `install --mode new --activate` без записи.
3. Покажи единый план подключения: файлы кита, навыки, дополнение инструкций, выбранные пакеты навыков.
4. Примени тот же набор параметров с `--apply --plan-id PLAN_ID`, затем выполни проверку активации.
5. Уточни цель продукта, стек и критерии приёмки. Зафиксируй требования и OpenSpec, согласуй существенный дизайн при UI.
6. Подтверди доступность моделей и инструментов на безопасном задании. Создай задачу и приступай к реализации.

Режим `new` допускает только начальные файлы: Git, README, лицензию, gitignore и инструкции. При наличии рабочего кода используй существующий проект.

## Существующий проект

1. Проверь Git и незакоммиченные изменения. Не стирай их и не создавай коммит без соответствующего поручения.
2. Выполни `inspect` и `install --mode existing --activate` без `--apply`.
3. Изучи конфликты и дополнение `AGENTS.md`. Получи разрешение на конкретный план, если оно ещё не дано.
4. Примени план по `plan_id` и проверь результат. Исходные инструкции сохраняются, конфликтующие навыки не перезаписываются.
5. Исследуй модули, API, данные, миграции, тесты, интерфейсы, зависимости, безопасность и неявные машины состояний.
6. Зафиксируй исходное состояние: выполненные проверки, уже существующие дефекты и ограничения. Итог обследования оформи по шаблону [BROWNFIELD_REPORT.md](../templates/BROWNFIELD_REPORT.md).
7. Новые изменения оформляй в OpenSpec и выполняй через общий процесс задач. Технический долг учитывай отдельно.

Файл `.agentic-kit/ADOPTION.md` содержит предварительную инвентаризацию имён файлов и инструментов в PATH. Он не заменяет обследование кода.

## Пакеты навыков

**Профиль риска** (`lite`, `standard`, `critical`) задаёт строгость проверок и описан в [METHODOLOGY.md](METHODOLOGY.md). **Пакет навыков** это устанавливаемый набор для конкретной технологии. В командах параметр по-прежнему называется `--profile`.

Выбирай только необходимые пакеты: `web-development`, `qa-playwright`, `security-audit`, `database-postgres`, `ai-evaluation`, `knowledge-base`, `codebase-audit`.

Их можно включить в общий согласованный план подключения через `--activate --profile NAME`. Для уже установленного кита используй отдельные `aek_activate.py plan/apply/check`; при `apply` обязателен `--plan-id`. Повторный параметр включает несколько пакетов. Это регистрирует навыки, но не устанавливает внешние пакеты.

Для обследования большого проекта начинай с ограниченного анализа. Полный аудит требует определённого объёма, бюджета и прав. Найденные замечания проверяются до превращения в задачи.

## Безопасность и границы

- Предварительный план не записывает файлы.
- Изменение просмотренных файлов или набора пакетов навыков делает старый `plan_id` недействительным.
- Символические ссылки в управляемых путях и конфликты блокируют операцию.
- При обычной ошибке записи завершённые изменения восстанавливаются; аварийное завершение требует проверки состояния.
- Повторная установка при наличии манифеста запрещена. Для новой версии используй [обновление](UPGRADE.md).
- Инструменты и навыки, установленные пользователем независимо, не переходят под управление автоматически.
- Подключение не гарантирует восстановление всех требований существующего приложения или отсутствие регрессий.

Точные команды и проверка загрузки в T3 Code описаны в [BOOTSTRAP.md](BOOTSTRAP.md).
